## 本阶段排掉的 11 个真实缺陷

全部由自检或 jsdom 复现捕获，且**没有一个源于"库不好用"，都是接口或时序假设错误**：

| # | 缺陷 | 根因 | 影响 |
|---|---|---|---|
| 1 | 块级公式无法替换回文档 | 试图对 ProseMirror 文档按位置替换子节点——该 API 并不存在 | 公式解析出但内容丢失 |
| 2 | 高亮完全没颜色 | 把语言**别名**（`ts`/`js`）当语言名注册；highlight.js 11 只认 `registerAliases` 声明的别名 | `getLanguage('ts')` 返回 undefined |
| 3 | 高亮函数返回正确 HTML 但页面无颜色 | `<template>` 的内容在 `template.content`（DocumentFragment），不在 `template.childNodes` | 遍历到空集合 |
| 4 | 染色成功但立刻被抹掉 | 在 NodeView 构造/`update()` 期间改 `contentDOM`，被 ProseMirror 随后的 DOM 同步用纯文本覆盖 | 时序问题 |
| 5 | 表格里出现乱码 `�` | 哨兵字符用了 `\u0000`，markdown 序列化器把它替换为 U+FFFD | 输出被污染 |
| 6 | 单元格丢失加粗/代码 | 用块级 `parse` 解析内联内容，标记先被包成段落再文本化 | 标记静默消失 |
| 7 | 单元格内容丢标记（第二轮） | 序列化用 `textBetween`（只返回纯文本）而非渲染内部 markdown | 上一个缺陷的镜像问题 |
| 8 | 表格单元格内容类型受限 | `tableNodes` 的 `cellContent` 只接受 `paragraph`，起初误以为可用表格节点做嵌套验证 | 结构不合法导致构造失败 |
| 9 | 模块循环依赖 | `table.ts` 引用 `schema.ts`，而 `schema.ts` 又要导入 `table.ts` | 已在导入结构上规避 |
| 10 | **自检进程 OOM 崩溃** | 图片解析器的监听器用 `Set` 累积，而 NodeView 每次 `render()` 都传入**新闭包**，集合无限增长；`notify` 遍历时逐个触发 `render()`，形成"渲染→注册→通知→渲染"循环 | 进程被 GC 拖死 |
| 11 | 图片占位断言不稳定 | 路径解析要走主进程 `fs.stat` 往返，耗时不确定；固定等一帧不足以覆盖 | 断言时好时坏 |

### 缺陷 10 的教训

这是本阶段最严重的一个：**"每次渲染都注册回调"在集合类容器里等同于内存泄漏**。

修复方式是承认约束——同一个 source 只对应一个 NodeView，因此**只保留一个回调**即可，
并在登记时判断"是否已存在"而不是无条件添加。

同一类问题在事件监听、观察者模式里普遍存在。判断标准很简单：
**注册动作是否可能被重复执行？如果是，容器就必须是幂等的（Map 覆盖）而不是累积的（Set 添加）。**

### 缺陷 6 与 7 是一对

这两个是同一条链路的正反两面，值得单独记：

- **解析侧**：单元格内容是**内联** markdown，不能走块级 `parse`。正确路径是加一个
  私用区哨兵字符前缀后 `parse`，再取该段落的子节点（`MarkdownParser` 只暴露 `parse`，
  没有内联入口）。
- **序列化侧**：不能把单元格内容经 `textBetween` 取文本——那会丢掉所有标记。
  必须**递归手工渲染**内部 markdown。

只修其中一侧，表现为"能解析但存盘丢格式"或反之，很容易误判成同一个 bug 没修好。

### 缺陷 1 的正确解法

ProseMirror 没有"按位置替换子节点"的公开 API。正确做法是**自底向上重建**：
每层重新组装 `Fragment` 后 `node.copy(...)`。

替换点用**节点对象身份**（`Map<Node, Node>`）而非位置匹配——
重建过程中位置会变，对象引用稳定，因此不会出现"改一处影响另一处"。

### 缺陷 4 的取舍

染色必须推迟到 ProseMirror 完成 DOM 同步**之后**。微任务不够（同步也在微任务里，
排队顺序无保证），需推迟到下一帧。

代价：颜色晚一帧出现（肉眼不可见）。
收益：颜色不会被内核覆盖。

这个取舍也意味着**任何"设置内容后立刻查 DOM"的断言必须先等一帧**——
自检里有 3 处断言因此调整，并把等待封装成 `nextFrame()` 辅助函数，
避免后续再踩。

## 代码块高亮的关键设计

**不做**"把代码按 token 拆成多个 DOM 节点"的渲染方式——那会让光标定位、IME、
撤销全部失效。

采用"**单一文本节点 + 事后染色**"：

1. 内容保持为一个文本节点，contenteditable 行为完全由内核管理
2. 每次内容变化后，给这个文本节点内部的字符区间批量套 `class`

高亮因此只是"视觉叠加"，不参与文档模型，不破坏任何编辑行为。
代价是无法做细粒度 token 交互（编辑器里不需要）。

## 表格实现的关键取舍

| 决策 | 原因 |
|---|---|
| 复用 `prosemirror-tables` 的 schema 与命令 | 增删行列要正确处理 `colspan`/`rowspan`、合并单元格边界、表头切换，自写几乎必然在边界上出错 |
| 单元格内容用 `paragraph`（库的默认） | 与库命令的结构假设一致，避免"命令能用但结构非法" |
| 列宽 `colwidth` 不写入 markdown | 管道表本身无法表达列宽，往返时自然丢弃；刻意不为它发明私有语法 |
| 表格也走"抽取/回填" | 管道表的对齐行（`:--:`）在 markdown-it 的 core 阶段才被识别，而 prosemirror-markdown 只消费 token 流，拿不到原始对齐信息 |
| 抽取顺序：**先表格、后块级公式** | 表格单元格里可能出现 `$$`，顺序反了会把单元格内容误抽成块级公式 |

## 图片实现的关键取舍

| 决策 | 原因 |
|---|---|
| 字节走 `file.arrayBuffer()`，不走 dataURL | dataURL 有 base64 膨胀（+33%）且需在主进程再解码；ArrayBuffer 是更短且无损的路径 |
| 文件名用"时间戳 + 随机后缀" | 原文件名常含空格/中文/重名，直接落盘既易冲突又让 markdown 里布满转义 |
| markdown 存**相对路径** | 换机器、换目录仍能工作；绝对路径一旦移动就全断 |
| 图片落点限制在工作区外也允许 | 用户完全可以编辑工作区外的独立文件，其资源理应写在那个文件旁边；这里只校验扩展名白名单与路径穿越 |
| CSP 增加 `file:` 到 `img-src` | 渲染层由 dev server 加载时源不是 `file://`，不放开则本地图片一律被拦 |

## 人工验收发现的缺陷：代码块里退格"没反应"

这是在 L3 完成、用户实际试用后报告的缺陷，**自动化断言当时全部通过**——
因为断言覆盖的是"删除能同步回模型"，而没有覆盖"焦点在哪里"。

### 定位过程

先复现，不猜。用 jsdom 写了 `scripts/probe-code-backspace.mjs`，分别验证退格
依赖的三个环节：

| 环节 | 验证结果 |
|---|---|
| 键映射是否吞掉按键 | ❌ 没吞（`handleKeyDown` 返回 falsy，走浏览器原生删除） |
| DOM 变化能否同步回模型 | ✅ 能（`1111` → `111`） |
| **焦点是否还在编辑区** | ⚠️ **问题在这里** |

### 根因

代码块 NodeView 的 `stopEvent` 有意把 header 区域的事件交还给浏览器
——语言下拉框需要原生行为，否则会被 ProseMirror 吞掉。

**副作用是：从下拉框选完语言后，焦点停留在 `<select>` 上。**
此后所有按键（包括退格）都被下拉框吃掉，用户看到的现象就是"退格没反应"。

这个缺陷有个共同特征：**它不在数据流里，而在焦点里。**
所以所有"内容是否正确"的断言都发现不了它。

### 修复

1. **语言变更后把焦点还给编辑区**（核心修复）。
   用文本选区而非节点选区：节点选中的是整块，用户再按退格会删掉整个代码块。
2. **空代码块按退格退出为正文**。
   这是顺手修掉的相邻死路：原先命令对代码块直接 `return false`，
   而 baseKeymap 在块首也无能为力，于是"进代码块后出不来"。
   非空代码块不在此处理（会丢内容），块首且有前一块时交给 `joinBackward` 合并。

### 新增断言（共 4 条）

| 断言 | 覆盖 |
|---|---|
| 代码块内原生删除可同步回模型 | DOM → 模型的同步链路（真实 Chromium） |
| 空代码块退格退出为正文 | 退出手势 |
| 非空代码块块首退格不丢内容 | 防误删 |
| **切换语言后焦点回到编辑区** | 焦点缺陷本身 |

最后一条直接断言 `document.activeElement` 落在编辑区内，
这是**能抓住这类"焦点型缺陷"的断言形式**——值得在后续功能里沿用。

## 已知限制

- 高亮语言限于已注册的 14 种（其余退化为纯文本，不报错）
- 公式就地编辑需**双击**进入（原子节点无法直接输入）
- 块级公式首尾空行会被规范化去掉（保证往返稳定）
- 高亮颜色晚一帧出现（见"缺陷 4 的取舍"）
- 表格单元格内**不支持换行**（markdown 管道表本身不支持）
- 表格单元格内的块级内容（标题、列表）会退化为纯文本——管道表无法表达
- 图片**必须**先保存文档才能粘贴（未保存时没有落点，会提示先保存）
- 图片不做压缩/缩放，原样落盘
- 删除文档中的图片引用不会删除 `assets/` 里的文件（需手动清理）
- 任务列表 → 后续级别
- 导出 → L4
